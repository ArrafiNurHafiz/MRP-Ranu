# Modul 06 — Quality Control (QC)

Fase: F6. Entitas: `docs/02-model-data.md` bagian Inventory (warehouse quarantine, movement types), tabel baru `qc_checks`, `qc_reject_lines`.

## Tujuan

Semua barang masuk dari pembelian, maklon, dan produksi internal melewati inspeksi QC sebelum boleh dipakai. Penerimaan fisik masuk ke gudang karantina; pass lepas ke gudang tujuan, reject di-return/dispose ke vendor/internal. Ledger tetap konservatif: tidak ada stok yang muncul dari udara.

## Konsep gudang karantina

- Setiap gudang internal memiliki satu gudang karantina berpasangan (dibuat otomatis saat gudang dibuat). `warehouses.is_quarantine = true`.
- Stok karantina terlihat di `stock_balances` tetapi **tidak bisa dialokasikan atau diissue**. Keluar hanya lewat movement QC (`qc_release`/`qc_reject`/`purchase_return`). Alasan: alokasi stok yang belum lulus QC menciptakan risiko "stok palsu tersedia".

## Aturan bisnis

1. **Terima fisik → karantina:** saat PO/receipt, SCO receipt, atau WO completion dibuat, barang di-mutasi ke gudang karantina tujuan, bukan langsung ke gudang usable. PO receipt → quarantine gudang penerima; SCO receipt → quarantine gudang internal tujuan; WO completion → quarantine gudang tujuan WO.
2. **QC check:** per item per dokumen (receipt line / completion), catat: `qty_received`, `qty_inspected`, `qty_pass`, `qty_reject`, metode `full` atau `sampling`, `inspector_id`, `checked_at`, catatan.
3. **Metode sampling v1:** seluruh lot diterima atau ditolak. Tidak ada estimasi proporsional. `qty_pass + qty_reject = qty_received`. Jika `qty_inspected < qty_received`, sampel gagal → seluruh lot ditolak.
4. **Pelepasan karantina (atomik dalam satu transaksi):**
   - `pass` → movement `qc_release` quarantine → tujuan akhir (PO → gudang PO; SCO → gudang tujuan SCO; WO → gudang FG WO).
   - `reject` → movement `qc_reject`/`purchase_return`/`transfer` sesuai disposition:
     - `return_supplier` (PO): movement `purchase_return` quarantine → virtual supplier.
     - `return_vendor` (SCO): movement `transfer` quarantine → gudang vendor terkait SCO.
     - `rework` (WO): movement `qc_reject` quarantine → virtual produksi (kembali ke proses).
     - `scrap` (PO/WO/SCO): movement `scrap` quarantine → virtual. Membutuhkan alasan wajib dan referensi QC check.
5. **Backflush SCO pada receipt:** saat SCO receipt dibuat, backflush komponen `stock` dari gudang vendor untuk seluruh `qty_received` fisik meskipun belum QC. Jika FG nanti ditolak QC, komponen sudah habis di vendor; vendor wajib mengirim kembali material atau mengganti (di luar cakupan pembayaran v1, tapi reject dijadwalkan ulang dalam SCO yang sama: `qty_rejected` mengurangi sisa SCO yang harus vendor kirim). Kehilangan di vendor tercatat di ledger, bukan disembunyikan.
6. **Penyelesaian WO:** WO completion yang lulus QC = qty yang menambah saldo FG. WO yang ditolak: completion tidak dihitung dalam WO; WO perlu completion tambahan untuk mencapai target. WO dapat menerima completion ulang (bukan edit completion lama).
7. **Kunci QC:** movement keluar dari gudang karantina tanpa `qc_check` berstatus `passed`/`rejected` untuk qty tersebut → tolak `QC_REQUIRED`. Sebelum QC, barang tidak bisa dipakai di issue/produksi/pembelian lain.
8. **Divisi:** `quality` dapat menilai; `warehouse` memposting receipt dan memindahkan hasil QC; `admin` dapat override QC check dengan alasan tercatat. Akses diatur di `docs/04-hak-akses.md`.

## Alur utama

1. Receipt/post movement → karantina.
2. QC check → catat pass/reject + disposition.
3. Pelepasan karantina → movement sesuai hasil.
4. Reject return/disposal tercatat.

## Kriteria penerimaan

- [ ] PO receipt masuk ke karantina; QC pass lepas ke gudang, reject kembali supplier; PO line `accepted` bertambah hanya setelah pass (test).
- [ ] SCO receipt masuk karantina; backflush komponen terjadi saat receipt; QC pass lepas ke FG, reject ke gudang vendor; SCO accepted qty bertambah hanya setelah pass (test).
- [ ] WO completion masuk karantina; QC pass lepas ke FG, reject rework/scrap; WO hanya terhitung completed untuk qty pass (test).
- [ ] Movement dari karantina tanpa QC check ditolak `QC_REQUIRED` (test).
- [ ] Sampling reject seluruh lot; qty_pass+qty_reject=qty_received (test).
- [ ] Disposition return_supplier hanya untuk PO, return_vendor hanya untuk SCO, rework hanya untuk WO (test).
- [ ] Stok karantina tidak bisa dialokasikan/diissue (test).
- [ ] Konservasi stok internal + vendor setelah end-to-end dengan QC (test).
